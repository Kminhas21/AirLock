## 3. Findings

| # | Severity | Finding |
|---|---|---|
| none | BLOCKING | None found. |
| S1 | should-fix | `--post-hoc` silently overwrites an earlier post-hoc result (`results_v3_posthoc.json`, `REPORT_V3_POSTHOC.md`): probe showed a second `--post-hoc` run rc 0 replacing the first. A chain of reruns after seeing scores is exactly what the honesty rules want visible. Suggest refusing or timestamp/numbering the post-hoc files, and optionally requiring that the original `results_v3.json` exists. |
| S2 | should-fix | Overwrite protection keys only on `results_v3.json`. If only `REPORT_V3.md` exists (json deleted), the non-post-hoc run proceeds and overwrites it (probe: rc 0). Check both files, or write via exclusive-create. |
| S3 | should-fix | There is no test that pins the PER-TRACE registry assignment (finding f) or that a v3 parse never precedes the guard; both hold today (my fixtures), but only by code order. Suggest adding the two fixtures from probe_cf.py (garbage v3 + changed input -> rc 3; fwd == reverse == alone scores) as tests. The existing refusal test (test:595) checks only that no output was written. |
| N1 | note | C2 has no minimum n (spec has none) and C2/C5 fail closed on NaN (empty listed stratum, missing `benign_ext_v3`). Defensible, but a reader may see `FAIL` where "no data" is meant; the report prints the value `n/a`. |
| N2 | note | The T06 ticket text says the runner refuses if the frozen file is newer than the adjudicated data (mtime guard). That is replaced by the provenance guard per Amendment 3 (docstring :10-15 says so); the report and honesty items state it. Provenance is self-attested (hashes recorded by the fitter); the guard proves consistency with allowed inputs and absence of v3 references, not that the fit really ran blind. This is the limit Amendment 3 already declares. |
| N3 | note | `--post-hoc` banner says "Declare why next to the numbers" but there is no `--reason` argument, so the declaration is left to the human. |
| N4 | note | The verdict `label` is `qualifies` (not `provisionally qualifies`); PROVISIONAL is in the message, the report banner, `provisional: true` and the recommendation text, so the requirement is met, but a consumer reading only `label` would miss it. |
| N5 | note | Latency is one measurement (largest authored1 registry) reused for all conditions; documented in the report. Strata for authored2/oracle are computed under their own registries (correct by Amendment 3), so C2/C8 differ per condition; this is reported. |
| N6 | note | Precedence listed > stale > missing means a first violation with both a listed token and an unregistered-external token counts as `listed`; the report counts these (`masks_missing`) so the reader can see how many. |
