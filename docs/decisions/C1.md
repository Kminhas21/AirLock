# C1 event builders + contract test (bug B8)

## What was done
- `tests/contract/test_events_contract.py` written first (red: 10 failed, `events` module missing), then `server/events.py` (green: 15 passed).
- The test parses `frontend/src/types/contracts.ts` (comments stripped, brace-depth scan so nested object types such as `coordinates`/`metrics` do not leak keys, `?` = optional) and checks builder key sets, builder existence per server-sendable event (all except legacy `task_complete`), and every event in `demo/cached_runs/*.json` (ignoring `delay_ms`).
- Drift self-test: renames `agent_response` -> `agent_reply` in a copy of the contracts text and asserts both the missing and unexpected field are reported.

## Decisions
- Contract is authoritative: `tool_resolved` has `agent_response` (default ""); `session_complete` has `reason` + `message` + `timestamp`; `alignment_alert` has no timestamp (contracts.ts has none); `error` has only `message`.
- Positional args for contract fields, `now=` keyword-only for timestamps.
- Builders do not validate enum values (the gate/loop own semantics); the test checks key sets only, as specced. Value-level literal checks rejected as out of scope.

## Findings: existing code vs contract (for integration)
- `agent_loop.py` currently violates the contract: `alignment_alert` uses `alert_type/detail/timestamp`, `drift_update` sends `drift_score/denied_categories/circumvention_count`, `tool_resolved` lacks `agent_response`, `session_complete` lacks `reason`/`timestamp`.
- Cached runs `aligned_run.json` and `adversarial_run.json`: NO violations found, so no xfail was added (`XFAIL_RUNS` dict in the test is the hook if that changes). `server/cached_runs/aligned_demo.json` is outside this test's glob and was not checked.

## Residual risk
- Regex parser handles the current simple interface style; exotic TS (generics, multi-line unions with `;` inside) could need extension, though the parser sanity test would flag breakage.
