# T1 drift tracker (B6)

Traced: in agent_loop.py `check_circumvention` ran only on the approve path, so a
circumvention attempt that the human denied (deny send_email, then agent proposes
send_slack_message, denied too) was never counted: circumvention_count stayed 0 and
drift_score 0.

Fix: `DriftTracker.observe_call(tool)` is meant to be called at proposal time, before
the human decides. It increments total_actions always, and circumvention_count iff the
tool's category is already denied and the tool is not itself a denied tool.
`check_circumvention` kept as a deprecated alias. `drift_score` clamped to [0,1]
(also guards total_actions <= 0).

Tests: regression scenario; a test double modelling the original check-on-approve-only
wiring shows it yields 0 for the same scenario (documenting why the fix is at the call site).

Rejected: counting inside `record_denial` (would conflate the denial of the first tool
with circumvention and miss approved attempts); returning a flag from the loop only
(not testable in isolation).

Residual risk: agent_loop.py must be changed by integration to import this class and
call `observe_call` on proposal, before awaiting the decision; until then the bug persists
in the live loop. A denied tool re-proposed itself is not circumvention (persistence is
tracked via check_goal_persistence). Unknown tools have no category, so are never flagged.
