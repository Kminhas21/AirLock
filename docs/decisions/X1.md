# X1 end-to-end acceptance tests (all bugs, black-box)

Files: `tests/e2e/test_ws_session.py`, `tests/e2e/fakes.py`. Written from SPEC.md (X1), DECISIONS.md and
`frontend/src/types/contracts.ts` only. `server/main.py` was read for the entrypoint/patch names
(`main.app`, `main.get_client`); `agent_loop.py` logic was not read to decide expectations.

## Design
- `FakeClient` replays a script of openai-shaped turns (or raises scripted exceptions). `main.get_client` is
  monkeypatched to hand out one client per session (so concurrency tests give each session its own script).
  An exhausted script answers with a plain-text final turn, so a looping server cannot spin on an empty script.
- Hang guard: every websocket interaction runs in a daemon thread joined with a timeout (`fakes.guarded`, 8 s default,
  shorter where the scenario is short). A hung server fails the test with the events seen so far.
- `drive()` receives until disconnect, OR until a terminal event followed by `TERMINAL_GRACE_S` (0.2 s) of silence
  (so a server that forgets to close does not cost a full timeout per test). Anything received after the terminal
  is appended, so "exactly one terminal, and it is last" is observable. `Events.closed` records whether the server
  closed; `test_connection_closes_after_session_complete` asserts it (main.py's documented behaviour).
- Contract validation: `fakes.load_contract()` parses contracts.ts (interfaces in the `ServerEvent` union, type aliases,
  `?` optionals, inline object types) and checks EXACT key sets plus value types (string/number/boolean/null,
  literal unions, nested objects). `task_complete` is deliberately not accepted from the real server.
  tests/contract did not exist, so the parser is re-implemented here.
- Side-effect checks are black-box: instead of peeking at the environment (it lives in the server's task context),
  a later approved `read_file` in the same session must (not) return the content of an earlier write.
- Gate timeout seam: `patch_gate_timeout` sets `SENTINEL_GATE_TIMEOUT_S`, patches every module attribute named
  `GATE_TIMEOUT_S` (gate, agent_loop, main when present) and the captured default of `gate.await_decision`
  (a `timeout=GATE_TIMEOUT_S` default is bound at def time and would ignore the attribute). Needs `gate.py` per G1 spec.
- Replay and retry tests patch `asyncio.sleep` to cap delays at 1 ms (cached runs carry ~10 s of `delay_ms`; backoff).

## Interpretation choices (ambiguities in the spec)
- #1/#5/#6: terminal reason on a normal finish is `finished` (contract enum). #5 requires no approved resolution and a
  `session_complete(gate_timeout)`; a `tool_resolved(deny)` before it is allowed but not required. #6 accepts
  `session_complete(llm_error)` or `error` (spec: "or `error`") as the single terminal.
- #3 forgeries each carry the opposite of the real decision, so honouring a forgery flips the observable outcome
  (otherwise "approve forged, approve real" would pass vacuously). Non-JSON-object forgeries use valid JSON
  (list/string/number/null); raw non-JSON text is only used in #12 (G1 spec says receive exceptions propagate).
- #4 garbage values: "APPROVE", "Approve", "yes", "true", "", null, 1, true, ["approve"], "approve " and a missing key.
- #7 asserts `len(fake.calls) == 3` (two retries) per L1 spec.
- #8 asserts at least one `alignment_alert` (severity in the contract enum, linked_node_id a known node) and
  contract-shaped `drift_update`s when both attempts are denied. It does not assert numeric drift values.
- #10 compares replayed event names with `demo/cached_runs/{scenario}_run.json` in order, then requires exactly one
  appended `session_complete(finished)` (the cached files end on a drift_update/alert, and the contract says the server
  ALWAYS sends a terminal). Extra key `delay_ms` must not leak (strict key sets).
- #13 uses a live fake-LLM session as the acceptance probe (not replay), so auth tests do not depend on replay support.
  "Rejected" = no session events delivered (a bare `error` before close is tolerated).
- B15 (`str(e)` leaked) is covered by `test_llm_error_text_not_leaked_to_client` (DECISIONS B15, not in X1 list).
- #11 uses two overlapping sessions plus a later third: A writes, pauses on a pending read; B starts, writes, reads A's
  file, finishes; A resumes and must still see its own file and not B's; C must see neither.

## Residual risk
- The concurrency test can only prove isolation for the sequences exercised.
- Grace-based terminal detection assumes a localhost server emits trailing events within 0.2 s.
- Tests couple to tool names/mock-environment behaviour only through public strings in SPEC (`[DENIED`, tool names).
