# G1 gate (B1 B2 B7)

Traced: agent_loop blocks on a bare `receive_json()` and trusts the first message; any message (wrong node, wrong event) could approve/deny, and there was no timeout or duplicate guard.

Design: `server/gate.py::await_decision` loops, ignoring (WARNING) non-dicts and non-matching event/node_id. Approve only on exact `"approve"` (strict `str ==`, so `True`/`1` fail). Total deadline via `loop.time()` and `wait_for(remaining)`, so ignored chatter cannot extend it. `DecisionLedger` is an instance (no module state) so sessions do not share claims.

Decisions on ambiguity:
- Explicit `"deny"` => `("deny","human")`; any other value (missing, None, "yes", "APPROVE") => `("deny","invalid")`. Spec only said "anything else => invalid"; treating exact "deny" as a human decision seemed the only sensible reading given the `human` reason exists.
- A `TimeoutError` raised by the websocket itself (before deadline) is re-raised rather than converted to a denial ("any receive exception other than timeout propagates" is read as: only our deadline timeout is swallowed).
- timeout=0 or negative => immediate timeout denial without receiving.

Rejected: per-receive `wait_for` (resets on noise); global ledger set (leaks across sessions).

Residual risk: agent_loop must still call `ledger.claim` and handle `WebSocketDisconnect`; integration is out of scope. A client can never see a distinguishing result between deny reasons unless loop surfaces `reason`.
