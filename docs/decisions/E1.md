# E1: per-session mock environment (bug B4)

Problem: `MOCK_FS`/`MOCK_DB`/`*_LOG` were module globals, so concurrent websocket
sessions shared state and one session's `reset_environment()` wiped another's.

Decisions
- `Environment` is a dataclass (`fs`, `db`, `email_log`, `slack_log`, `webhook_log`,
  `shell_log`, `github_issues`); defaults are deep-copied per instance.
- Held in `ContextVar` `_ENV` with no default and nothing set at import. A value set
  at import would be copied into every child task's context and shared.
- `get_environment()` lazily creates; `reset_environment()` installs a fresh env in
  the current context and returns it. asyncio tasks each get their own context copy,
  so a reset inside a task is invisible to siblings and to tasks started later.
- Caveat: a task inherits whatever env its parent context already holds at creation
  time (then diverges on its own reset). Session entry points must call
  `reset_environment()` inside the per-session task.
- `exec_*` signatures and outputs are unchanged. Old globals removed (grep showed no
  other importers; `server/tools.py` imports only `exec_*` and is untouched).
- Preserved quirk: shell prefix matching maps `git log` to the `git status` output
  (first same-binary entry wins); pinned in a test rather than silently altered.
- Regression test runs in an empty `contextvars.Context()` so test order cannot leak
  an env into it. Red before the refactor: session A's write was wiped by B's reset.
